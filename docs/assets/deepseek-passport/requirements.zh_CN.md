# DeepSeek Passport 产品需求

本文档记录产品负责人提出了什么、需求如何被拆解，以及还有哪些内容尚未决定。
它是本 fork 的权威需求来源。硬件事实来自
[`components/bsp/include/bsp_pins.h`](../../../components/bsp/include/bsp_pins.h)
与[硬件指南](../../hardware-design/AI_HARDWARE_DEVELOPMENT_GUIDE.md)；
满足这些需求的设计见 [architecture.md](architecture.md)。

记录日期：2026-10-13。记录自一份口头/书面的产品简述；
记录者添加的每一处解读都被标记为假设（`A-*`），而不是需求。

## 1. 产品概述

一台基于 FoloToy AI Passport 板卡的口袋尺寸 DeepSeek 伙伴设备。它首先是一个
宠物 —— 一个生活在主页面上的可交互像素角色 —— 其次才是一个语音终端和桌面
智能体遥控器。它平时处于空闲状态；按下按钮即可唤醒。

## 2. 范围

范围内：

- 面向原装 AI Passport 板卡（`ESP32-C3`，8 MB Flash，无 PSRAM）的应用固件。
- 用户电脑上的配套 Passport 桥接服务进程，负责提供商编排，并把 DeepSeek Harness 会话镜像到设备。
- 通过接入点、二维码和配网门户页进行 Wi-Fi 配网。
- 设备自托管的 Web 后台，用于配置和更新。
- 原创像素风 UI、动画素材和像素 CJK 字体。
- 双语文档和带日期的进度日志。

本项目范围外：

- 任何硬件改动、额外接线或板卡改版。
- 替换或重写上游 BSP 内部实现。
- 多租户云服务。
- 复用上游演示测试菜单或其视觉外壳作为应用 UI。

## 3. 功能需求

标识符是稳定的，并被架构和路线图文档引用。`MUST` 是硬性需求；`SHOULD` 是
省略时需要记录取舍的需求。

### 3.1 R-A 主页面与宠物交互

| ID | 需求 | 说明 |
| --- | --- | --- |
| R-A1 | 主页面必须（MUST）就是宠物本身，而不是列表或菜单。其他每个页面都通过显式操作进入。 | 产品负责人：“首先是主页面，是 deepseek 的 Q 版形象” |
| R-A2 | 宠物必须（MUST）是一个原创 Q 版像素角色，具备待机呼吸、眨眼和至少四种不同反应（开心、思考、聆听、睡觉）。 | 用户要求像素风；素材必须为原创 |
| R-A3 | 宠物必须（MUST）以屏幕上的对话气泡展示对话，包括用户的转写文本和回复。 | 产品负责人：“从屏幕上气泡对话” |
| R-A4 | 主页面必须（MUST）显示一条紧凑状态栏：Wi-Fi 状态、电量、工作模式状态和麦克风状态。 | 让宠物无需进入菜单即可使用 |
| R-A5 | `OK` 单击必须（MUST）把设备从待机唤醒并开始一轮语音对话。`OK` 长按必须（MUST）打开操作面板（设置、工作模式、休眠）。`UP` / `DOWN` 必须（MUST）在页面打开时循环宠物的反应或翻页。 | 保持现有的非阻塞输入契约 |
| R-A6 | 宠物必须（MUST）对输入、音量电平和智能体状态变化做出视觉反应。 | “可以和用户互动” |

### 3.2 R-B 实时语音对话

| ID | 需求 | 说明 |
| --- | --- | --- |
| R-B1 | 设备必须（MUST）采集麦克风音频，并从可配置的语音转文字（STT）后端获取文本转写。 | 建议的后端包括 Whisper 风格 HTTP 转写和 Gemini |
| R-B2 | 转写文本必须（MUST）发送到可配置的大模型（LLM）后端，默认使用 DeepSeek，并通过可配置的 base URL 支持 OpenAI 兼容端点。 | |
| R-B3 | 回复必须（MUST）通过可配置的语音合成（TTS）后端朗读，该后端应能输出自然听感的中文和英文。 | “这个语音也可以找一下一些api之类的做好听一点的” |
| R-B4 | 语音转文字（STT）、大模型（LLM）和语音合成（TTS）必须（MUST）各自可独立选择，并具备按后端分别设置的 API Key、base URL、模型和音色设置。 | “可以设置支持配置不同api后端” |
| R-B5 | 识别出的用户文本和助手回复都必须（MUST）在音频播放之前或播放过程中以气泡形式显示。 | |
| R-B6 | 默认交互必须（MUST）是半双工按键说话，或带可见说话结束提示的有界聆听窗口。全双工打断（插话）不是需求，因为目标芯片无法运行回声消除（AEC）。 | 见 `A-5` 和架构文档 |
| R-B7 | 设计必须（MUST）以级联方案在健康网络下将首段音频延迟中位数控制在至多 2.5 s，并且必须（MUST）在超过 1.5 s 时显示独立的“思考中”状态。 | |
| R-B8 | 网络或提供商故障必须（MUST）产生可见的错误状态、有界的重试策略，且不得造成音频通路死锁。 | |
| R-B9 | 对话必须（MUST）保留有界的多轮历史，且必须（MUST）不得让内部 RAM 无限增长。 | |

### 3.3 R-C 工作模式：桌面联动

| ID | 需求 | 说明 |
| --- | --- | --- |
| R-C1 | 设备必须（MUST）镜像用户电脑上运行的 DeepSeek Harness 会话的工作状态：空闲、思考中、工作中、等待输入、成功和错误。 | “当 deepseek 有进度的时候更新到 passport 上面” |
| R-C2 | 当设备空闲或处于待机时，收到新进度必须（MUST）更新主页面，而无需按下按钮。 | |
| R-C3 | 当智能体提供选项时，设备必须（MUST）渲染问题和选项，允许用 `UP` / `DOWN` 选择，并在 `OK` 时把答案发回。 | “从屏幕上显示，然后按钮选择和确认” |
| R-C4 | 问答载荷必须（MUST）保留每个选项的标签和用户的选择，并且必须（MUST）支持自由文本回答。 | |
| R-C5 | 一轮结束时，设备必须（MUST）根据用户设置播放提示音、朗读结果或保持静默。 | “设置滴声音通知或者是直接播报结果” |
| R-C6 | 设备必须（MUST）支持从工作模式向运行中的会话说出新的指令。 | “同时支持语音输入” |
| R-C7 | 工作模式集成必须（MUST）不得要求把电脑上的智能体 Web 服务器暴露到局域网。设备必须（MUST）仅通过带有自身认证的专用桥接服务访问智能体。 | 源自电脑侧威胁模型的安全约束；见架构文档 |

### 3.4 R-D 待机与电源

| ID | 需求 | 说明 |
| --- | --- | --- |
| R-D1 | 显示屏必须（MUST）在可配置的空闲时长后关闭，并且必须（MUST）在任意功能按键按下时恢复。 | “平时是待机。然后按一下按钮唤醒” |
| R-D2 | 待机必须（MUST）仍在可配置的延迟预算内呈现新的工作模式问题。 | 与深度睡眠冲突；通过显式电源模式解决 |
| R-D3 | 设备必须（MUST）显示电量，并在低电量时用可区分的动画和提示音告警。 | |
| R-D4 | 当工作模式投递被禁用时，设备必须（MUST）在可配置的空闲时长后进入深度睡眠，并且必须（MUST）在任意功能按键按下时唤醒。 | 按键唤醒保护行为在上游已存在，必须保留 |
| R-D5 | 设备必须（MUST）提供至少两种电源配置：保持网络和工作模式链路存活的连线配置，以及休眠并轮询的电池配置。 | 显式取舍，用户可选 |

### 3.5 R-E Wi-Fi 配网

| ID | 需求 | 说明 |
| --- | --- | --- |
| R-E1 | 在没有已保存凭据时，或在显式请求时，设备必须（MUST）启动 SoftAP 并在屏幕上显示二维码。 | “他没联网的时候就开热点，然后提供二维码联网” |
| R-E2 | 二维码必须（MUST）可扫描，并且必须（MUST）引导手机进入配网页面，而无需单独安装应用。 | |
| R-E3 | 配网页面必须（MUST）接受 SSID 和密码，必须（MUST）拒绝或警告仅 5 GHz 网络，并且必须（MUST）报告连接结果。 | |
| R-E4 | 用户必须（MUST）能够从设备 UI 和 Web 后台清除已保存凭据并重新进入配网。 | |
| R-E5 | 设备必须（MUST）不得在凭据存储之外以明文记录或持久化 Wi-Fi 密码。 | |

### 3.6 R-F Web 后台

| ID | 需求 | 说明 |
| --- | --- | --- |
| R-F1 | 配网完成后，设备必须（MUST）在其局域网地址上提供 Web 后台，可从手机浏览器使用。 | “之后的就是一个web管理页面” |
| R-F2 | 后台必须（MUST）能配置每个提供商：语音转文字（STT）、大模型（LLM）和语音合成（TTS）的 API Key、base URL、模型和音色。 | “配置 api key 等等” |
| R-F3 | 后台必须（MUST）能配置设备偏好：宠物名字、人设、UI 语言、音量、亮度、空闲超时、提示音策略、工作模式轮询和桥接服务地址。 | |
| R-F4 | 后台必须（MUST）提供自检：播放音调、朗读测试短句、运行一次对话补全，以及测试桥接服务连接。 | |
| R-F5 | 后台必须（MUST）支持空中固件更新，并且必须（MUST）显示正在运行的版本。 | |
| R-F6 | 后台必须（MUST）显示设备诊断信息：堆、最大空闲块、运行时长、Wi-Fi RSSI 和近期错误码，且不得暴露机密。 | |
| R-F7 | 机密从后台侧必须（MUST）是只写的：已存储的值只显示为已配置或未配置，绝不回显。 | |

### 3.7 R-G 像素 UI、素材与本地化

| ID | 需求 | 说明 |
| --- | --- | --- |
| R-G1 | 应用必须（MUST）实现自己的像素风视觉语言，并且必须（MUST）不得复用上游演示菜单、页面或外壳。 | 适用于衍生应用的上游强制规则 |
| R-G2 | 所有 UI 文本必须（MUST）提供简体中文和英文，并使用已在设备上验证字形覆盖的像素字体渲染。 | Montserrat 中的中文文本会渲染成空白方块 |
| R-G3 | 动画必须（MUST）由素材驱动，并且必须（MUST）不得耗尽 LVGL 内存池。每一个新增的常驻对象和每一个画布缓冲区都是一项内存决策。 | |
| R-G4 | 配色应当（SHOULD）源自 DeepSeek 品牌蓝，并在 240 × 320 显示屏上于一臂距离处保持清晰可读。 | |

### 3.8 R-H 数据与安全

| ID | 需求 | 说明 |
| --- | --- | --- |
| R-H1 | API Key 和桥接令牌必须（MUST）存储在 NVS 中，必须（MUST）不出现在源码里，并且必须（MUST）不得被记录到日志。 | |
| R-H2 | 桥接服务必须（MUST）用配对令牌认证设备，并且必须（MUST）仅绑定到局域网。 | |
| R-H3 | 仓库必须（MUST）不得包含凭据、设备二维码机密或未脱敏日志。 | 由仓库门禁强制执行 |

## 4. 非功能需求

| ID | 需求 |
| --- | --- |
| N-1 | 完整应用必须（MUST）仅在内置 SRAM 上运行。每个里程碑必须（MUST）在交付该功能的同时报告实测空闲堆和最大空闲块。 |
| N-2 | 固件必须（MUST）能在长时间空闲下不出现看门狗复位、断言或任务饥饿，并且必须（MUST）在反复进入/退出页面循环后回到相同的堆高水位线。 |
| N-3 | 硬件交互必须（MUST）留在 `components/bsp` 中；应用状态机、协议和布局计算必须（MUST）可脱离 ESP-IDF 或 LVGL 进行测试，并由宿主测试覆盖。 |
| N-4 | 每份维护中的文档必须（MUST）同时存在配对的英文和简体中文文件，并且[进度日志](progress-log.md)必须（MUST）随工作推进持续更新。 |
| N-5 | 固件必须（MUST）在 `feature/*` 分支上开发，以便 fork 的 `main` 与上游保持一致。 |
| N-6 | 固件必须（MUST）容忍每个可选子系统缺失：没有桥接服务、没有网络、没有电量计或没有音频设备时，都必须以可见状态优雅降级。 |

## 5. 假设

以下内容由记录者决定，以使需求集可执行。每一项都可撤销；
在实现冻结之前请确认或纠正它们。

| ID | 假设 |
| --- | --- |
| A-1 | 板卡为原装 AI Passport。不计划任何接线、引脚或元件改动。 |
| A-2 | 宠物是一个原创 Q 版鲸鱼，呼应 DeepSeek 品牌色，而非官方 DeepSeek 标志。不复制任何上游或第三方美术素材。 |
| A-3 | 配套的 Passport 桥接服务运行在用户电脑上，与设备处于同一局域网。 |
| A-4 | 提供商端点可从用户网络访问。由于部分海外提供商无法从中国大陆直接访问，每个后端都必须接受自定义 base URL。 |
| A-5 | 唤醒词检测不在范围内：目标芯片无法运行乐鑫语音识别前端，因此麦克风仅在用户请求时才打开。 |
| A-6 | 首个版本仅支持简体中文和英文，且为竖屏方向。 |
| A-7 | 假定单一用户和单一设备配置。没有多账号模型。 |
| A-8 | 设备通过 USB-C 充电，预期放在桌面或口袋里，因此连线供电配置是正常使用模式而不是例外。 |

## 6. 待决问题

| ID | 问题 | 为什么重要 |
| --- | --- | --- |
| Q-1 | 确认宠物的物种、设计方向和屏幕上的名字。 | 决定每一个像素素材和整个 UI |
| Q-2 | 默认的语音合成（TTS）后端和音色是哪一个？ | 决定默认配置、延迟预算，以及设备能否直接解码 PCM |
| Q-3 | 是否要求户外工作模式投递，还是首个版本仅同局域网可接受？ | 仅同局域网只需要本地桥接服务；远程投递需要项目目前还没有的中继服务 |
| Q-4 | 桥接服务缺失时，设备是否应能直接与云端提供商通信？ | 直连模式会把 API Key 和 TLS 放到设备上，是本项目最大的内存风险 |
| Q-5 | 是否需要在屏幕上显示流式部分转写，还是最终转写就足够？ | 流式意味着大得多的协议和内存投入 |
| Q-6 | 首个版本是否要求空中更新，还是 USB 烧录可接受？ | OTA 需要改分区布局并增加第二个应用槽位 |
| Q-7 | 是否应把设置 URL 写入被动 NFC 标签？ | 成本很低，但这是产品决策和一种数据格式承诺 |
| Q-8 | 默认电源配置是什么，电池配置下可接受的待机投递延迟是多少？ | 直接决定空闲电流和“不漏掉问题”的保证 |
| Q-9 | 宠物人设应是固定的系统提示词，还是可由用户在 Web 后台编辑？ | 影响提示词存储和配置界面 |
| Q-10 | 之后是否需要一小时的、放在口袋里的语音备忘录或长录音功能？ | 会改变现在的存储设计 |

## 7. 验收摘要

`Automated` 表示宿主测试或构建期检查可以作为门禁。`Device` 表示需要人员、
物理板卡和观察。构建成功永远不等于设备验收。

| 需求组 | 自动化 | 设备 |
| --- | --- | --- |
| R-A 宠物与主页面 | 布局计算、状态机、素材解码 | 动画流畅度、可读性、眨眼与反应时序 |
| R-B 语音对话 | 提供商请求/响应解析、分块、重试与超时逻辑、延迟统计 | 真实麦克风采集、真实播放、主观延迟与音质 |
| R-C 工作模式 | 桥接协议编解码、问题渲染模型、选择状态机、答案载荷 | 真实 DSH 会话镜像、提示音、朗读结果、不漏掉问题 |
| R-D 待机与电源 | 空闲定时器逻辑、进入休眠条件、唤醒原因处理 | 各配置的空闲电流、唤醒延迟、屏幕与音频恢复 |
| R-E 配网 | 凭据存储、二维码载荷构造、页面表单校验 | 手机扫码、iOS 与 Android 上的配网门户页行为、连接结果 |
| R-F Web 后台 | 配置模式校验、机密脱敏 | 手机上真实浏览器、实时提供商测试、OTA 更新 |
| R-G 像素 UI | 字体字形覆盖检查、素材大小与内存池预算 | 设备上中文文本渲染、动画内存余量 |
| R-H 安全 | 机密扫描、日志无凭据检查、NVS 往返 | 若启用，加密 NVS 的行为 |
