需求以 [requirements.md](requirements.md) 中的标识符引用；设计细节见
[architecture.md](architecture.md)。

## M0 —— 需求、架构与决策

**交付物：** `docs/assets/deepseek-passport/` 下的文档集、fork 的 readme
文件对，以及带日期的决策日志。

**退出标准：**

- 产品负责人要求的每一项能力，要么是已识别的需求，要么是明确记录的假设。
- 禁止某项能力的硬件约束要记录原因，而不是靠猜测。
- 待确认问题连同每个答案的后果一并列出。
- [进度日志](progress-log.md)记录读到了什么、决定了什么，以及还有什么未决。

## M1 —— 内存与音频预算可行性验证

**目标：** 在编写应用代码之前，用实测替换架构文档中的每一项估算。这个里程碑
可能以"否"收尾并改变设计，因此它被有意排在最前。

**交付物：**

- 一个最小固件，初始化显示屏、LVGL、按键通路和音频通路，启动 Wi-Fi station，
  并在每一步记录可用堆、最大连续空闲块和 `lv_mem_monitor()`。
- 一份测量报告：启动、Wi-Fi 之后、接入点启动之后、持续 PCM 采集之后、持续 PCM
  播放之后，以及十次屏幕进入/退出循环之后。
- 关于 LVGL 内存池大小、采集与播放环形缓冲区大小的决策，以及直连模式的服务商通路
  在 RAM 中究竟要付出多少代价——用活跃 TLS 会话实测，而不是估算。
- 进入并保持常连待机状态，以便用 USB 功率计在外部实测待机电流。固件无法测量自身电流——
  本板没有电流检测通路——因此这个数字属于仪器检查，在有人实测之前一直留在 `未验证项` 中。
- 一次音频环回检查：麦克风到扬声器走真实编解码通路，确认播放期间静音规则可以
  强制执行。

**退出标准：** 每个阶段都记录实测余量，每个阶段边界都已知最大连续空闲块，并且
用实测值修正架构文档中的数字。

## M2 —— 桥接服务、配置与文本对话

**目标：** 与 DeepSeek 的纯文本对话端到端可用，经由桥接服务完成，配置存储
在设备上。

**交付物：**

- 桥接服务，含三个提供方接口、每个阶段一个可用适配器，以及一个基于普通 HTTP、
  用令牌认证的设备 API。
- 设备端配置存储位于 NVS，带版本化 schema、默认值和密钥脱敏。
- Wi-Fi station 连接，带重连策略、凭证存储，以及一个不会阻塞 UI 的无网络状态。
- 一个最小应用外壳，且不是上游的演示菜单：主页面、文本输入路径，以及显示回复的
  对话气泡。
- 针对配置编解码、桥接协议编解码和会话状态机的宿主测试。

**退出标准：** 在设备上输入的消息由 DeepSeek 回答并显示在屏幕上；断开桥接服务会
产生可见、可恢复的错误；配置在断电重启后仍然保留。

## M3 —— 语音输入与语音输出

**目标：** 需求组 `R-B` 的口语对话闭环。

**交付物：**

- 16 kHz 单声道按键说话采集，仍在录音时就分块发送到桥接服务，带基于能量的
  话语结束判定和硬性最大时长。
- 经由桥接服务接通的语音转文字（STT），并显示转录文本。
- 流式回复文本、桥接侧的句子切分，以及按句合成。
- 按提供方原生采样率播放原始 PCM，会话期间在该采样率下打开编解码器。
- 播放期间强制麦克风静音，配一个状态机的宿主测试和一个设备上的回声检查。
- 一条延迟插桩路径，记录这一轮的每一段耗时。
- 直连模式通路：由设备对服务商端点执行同样三个阶段，TLS 会话严格串行化，并对每个
  响应设置大小上限。这属于范围内，因为产品负责人已批准（`Q-4`）。

**退出标准：** 需求 `R-B7` 是实测的，而不是断言的；回复可听且可懂；设备不会
转录自己的声音；屏幕动画期间播放不出现欠载。

## M4 —— 带实时智能体会话的工作模式

**目标：** 需求组 `R-C`，包括安全约束 `R-C7`。

**交付物：**

- 桥接侧仅通过本地智能体主机的回环接口与之对接，问题与通知来源要尽早验证，
  而不是假设。
- 面向设备的状态协议，带序列号、长轮询和确认。
- 进度渲染、带 `UP` / `DOWN` / `OK` 选择的问题屏幕，以及答案往返。
- 完成通知：按设置可选静默、提示音或语音播报。
- 从工作模式向运行中的会话发送语音指令。
- 针对设备休眠期间到达的问题的必达投递规则。

**退出标准：** 真实会话的进度显示在设备上；真实问题可从设备作答且智能体继续推进；
设备空闲时结束的一轮触发所配置的通知；在本里程碑使用的任何配置下，智能体主机都
不可从局域网访问。

## M5 —— 配网与 Web 后台

**目标：** 需求组 `R-E` 与 `R-F`。

**交付物：**

- 手写的接入点配网，屏幕上显示二维码，同时包含 Wi-Fi 关联信息与页面地址，
  一个通配符 DNS 响应器，以及连通性探测处理程序。
- 凭证仅在 station 连接成功后持久化。
- Web 后台：状态、配置、提供方测试、Wi-Fi 修改，以及维护操作。
- 控制台资源管线：单个自包含页面，构建时 gzip 压缩，嵌入 flash。
- Web 后台中的版本上报。空中升级（OTA）已推迟（`Q-6`），因此本里程碑不更改分区表。

**退出标准：** 工厂新设备无需任何配套应用即可从手机完成配网；Web 后台能配置每个
提供方并成功测试各自连通性；密钥绝不回显；配网服务随后被完全关闭。

## M6 —— 像素风宠物、美术、字体与本地化

**目标：** 需求组 `R-G`，以及产品真正的身份标识。

**交付物：**

- 资源管线脚本及其可复现输出，连同许可证、转换器版本和字节开销一并记录入库。
- Q 版鲸鱼宠物，含表情集和待机动画，由驻留 flash 的图像描述符绘制。
- 像素风中日韩字体子集，并在自动化门禁中做字形覆盖检查。
- 完整屏幕集合：主页面、对话、工作进度、问题、配网、二维码、错误和待机。
- 每个屏幕的简体中文与英文文案。

**退出标准：** 宠物动画播放不会增加常驻对象数量；中文在设备上渲染无空白方框；
每个屏幕都记录 LVGL 内存池高水位线；不复用上游演示的任何屏幕、卡片或菜单。

## M7 —— 待机、电源与发布

**目标：** 需求组 `R-D` 以及 `N-1` 至 `N-6`。

**交付物：**

- 空闲熄屏，以及任意功能按键唤醒，保留现有的按键唤醒保护行为。
- 以常连配置为默认，其待机电流须实测并在 Web 后台中说明。电池配置与深度睡眠已推迟
  （`Q-8`）；为它们保留上游的按键唤醒守卫行为不变。
- 深度睡眠进入条件，以及每种配置下的空闲电流测量。
- 电池指示和低电量警告动画。
- 发布打包：合并镜像、版本上报，以及完成检查清单。

**退出标准：** 每种配置都有实测空闲电流；在所述延迟内，两种配置下问题都不会丢失；
反复导航与空闲循环不泄漏堆、任务、套接字或定时器；发布检查清单已完成。

## 验证计划

| 层级 | 方法 | 适用范围 |
| --- | --- | --- |
| 仓库门禁 | `./tools/validate.sh --static` —— 仓库检查加宿主测试 | 每次变更 |
| 宿主测试 | 不依赖 ESP-IDF 或 LVGL 编译并运行的纯逻辑：状态机、协议编解码、配置编解码、问题渲染、空闲定时、二维码载荷构造 | 每个里程碑 |
| 固件门禁 | `./tools/validate.sh --firmware` —— 构建加合并镜像验证 | 每个固件里程碑 |
| 内存检查 | 启动与阶段边界的可用堆、最大连续空闲块和 LVGL 内存池监控日志；反复循环中的历史最小值 | `M1` 起 |
| 设备验收 | 每个里程碑明确的、人工观察的检查 | `M1` 起 |
| 安全检查 | 密钥扫描、凭证日志检查，以及智能体主机不可从局域网访问的检查 | `M2`、`M4`、`M5` |

每份交付报告都分别说明 Build、Host tests、Device tests 和 Unverified。绿色构建
绝不作为设备验证上报，且刷写设备始终需要明确批准。

## 项目的完成定义

- [requirements.md](requirements.md) 中每一项 must 级需求都满足并验证，或已正式
  降级，且产品负责人的决策记录在[进度日志](progress-log.md)中。
- Web 后台无需编辑源代码即可配置每个提供方。
- 工厂新设备通过纯手机设置即可达到可用的对话。
- 智能体主机绝不因本项目暴露到网络。
- [进度日志](progress-log.md)包含每项声明的证据。
